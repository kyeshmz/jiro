### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune confirmed merged or abandoned Git worktrees and stale iOS simulators to reclaim space. Deletion can discard user state. Every step guards against deleting something in use or holding uncommitted work.

1. **Snapshot and audit.** Record `df -h /`. Run the bundled audit helper relative to this playbook's directory as `scripts/worktree-audit.sh <repo-path> [--base <ref>] [--with-prs] [--session-export <file>]...`. It requires Bash and Python 3.9+. It reads exact paths from `git worktree list --porcelain -z`, never hand-typed paths. It reports size, age, local merge state, tracked edits, untracked and ignored files, upstream state, available PR state, and matches in explicitly supplied OpenCode session exports. `--with-prs` enables a read-only `gh` query when available and authenticated. Without it, PR state is unknown. The helper does not fetch, write Git refs, delete files, or scan global session storage. Record stale or unavailable evidence. The audit may be slow, so run it in the background when appropriate.
2. **The bucket is advice, not permission.** Record the user's pinned or active sessions and any background child sessions associated with the worktrees. OpenCode session metadata does not establish that a session is pinned. Ask the user when this cannot be observed. Cross-check every candidate. Missing session evidence is a hold, not proof that a worktree is unused.
3. **Verify usage before deleting.** Use only known session IDs from the current task or a user-approved set. Export each with `opencode api get /api/experimental/session/<sessionID>/export`. Confirm its ID and working directory before reading the messages. Inspect recorded tool calls for sibling worktrees created by child sessions as well as the session's own directory. Use OpenCode `explore` subagents for independent read-only transcript review when the histories are large. Never glob global session databases or unrelated projects. A session export is historical evidence, not a live activity check. Confirm current usage separately.
4. **Pause on loss.** Tracked edits, untracked files, and ignored files may all be user work. Show staged and unstaged diffs. Name untracked and ignored files. Do not infer that scratch files are disposable. Present the exact proposed deletion set and obtain explicit approval before deleting. Preserve in-use worktrees. Hold anything whose ownership, usage, or recoverability is uncertain. A clean merged branch does not authorize deleting unrelated files in its directory.
5. **Prune the approved set.** Re-check status and usage immediately before removal. Use `git worktree remove <exact-path>` without `--force`. If Git refuses, report why and stop on that path. Use `--force` only when the user explicitly approved the identified contents it would discard. Do not fall back to broad recursive deletion. If ignored artifacts remain, inspect and separately approve their exact paths. Keep branch refs. Run `git worktree prune --dry-run` first and prune only the reviewed stale registrations. Record `df -h /` afterward and re-list the worktrees.
6. **Simulators and other reclaimers.** Inventory before proposing deletion. Use `xcrun simctl list`, `xcrun simctl --set testing list`, and `xcrun simctl runtime list` when Xcode tooling is available. After approval of the exact devices or runtimes, delete only their IDs. `xcrun simctl delete unavailable` removes a set of devices, so its full set needs approval first. Avoid `delete all`. Xcode DerivedData, iOS DeviceSupport, and package caches such as pnpm, uv, brew, and yarn are additional candidates only within the approved scope. Never delete OpenCode session databases, credentials, logs, snapshots, or configuration as a substitute for clearing editor caches. Keep anything the user said to retain.

This playbook deletes user state with no code review to catch a slip. The approval and usage gates are the review.

**Reply.** Report `df -h /` before and after, the measured change in available space, the worktrees pruned, and a one-line reason for each held back. Name the session using a held worktree or the uncommitted files blocking removal. If concurrent disk activity prevents attributing the full change to this cleanup, label the attribution as an estimate.
