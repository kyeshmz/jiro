## Selection

- **Take.** One main skill selects a playbook, puts its steps first, loads companion skills as needed, favors simple code, verifies real behavior, and owns delegated work. Long runs use a decision trail. Replies remain concise and evidence-backed.
- **Adapt.** The entry ID is `jiro`, invoked as `@jiro` or through the `/jiro` command. Jiro coordinates the task, task playbooks are recipes, supporting skills are tools, and delegated workers are chefs. The registered Jiro worker ID is `chef`. Keep technical IDs and verification contracts precise. Use OpenCode tool arguments and base-directory resource resolution. Inherit the active model unless an authorized, host-confirmed override applies. Keep explicit invocation and existing user work protected.
- **Skip.** Cursor Custom Modes, `/loop`, editor plugins, model defaults, automatic PR creation, and mandatory calls to unbundled pstack skills or custom agents. Global installation and external writes require authorization. Do not treat an unattended request as blanket approval.
- **Jiro-native.** `references/recipes.md` provides compact workflows for the selected routing categories. It is not an import of pstack's individual playbooks or standalone principle skills. The command wrapper is repository-authored OpenCode configuration.

The import does not claim full parity with pstack's twenty-three playbooks. The four existing companion imports retain their own source pins. Repository maintenance remains outside skill discovery and installation. The existing cleanup playbook's unknown baseline is unchanged.

The added delegation and Microsoft Playwright ports have their own provenance records. Jiro routes to their exact skill IDs and delegates ownership of their contracts, isolation, and evidence formats rather than copying those procedures into the entry workflow. Instructions being bundled does not establish runtime availability.

The selected `no-comments` and `principle-laziness-protocol` tools also have their own pins and provenance. Jiro loads comment review before nontrivial code review and Laziness Protocol before refactoring or adding structure.

This checkout also preserves its local six-principle router, design and reader-load skills, Effect and React guidance, reflection, cleanup, and scoped Chef worker. Shared writing and autonomy rules remain in the materialized `references/shared-rules.md`. These local companions keep their own source records and are not newly imported from the entry workflow's source pin. The merged entry uses the new native recipe book without removing those local routes or model-authorization gates.

After the user requested MCP removal, browser work defaults to the CLI or an existing project harness. MCP instructions remain opt-in for an explicit request; Jiro must not configure or re-enable that server during ordinary verification or maintenance.
